11月20日のv2.6.0から1週間の更新です。この記事のDartの例は、`openci/pubspec.yaml` の `openci_workflow` を `^0.8.1` にして試せます。PRの調査には `openci_cli_plus` 0.9.0を使います。[ワークフローSDK](https://pub.dev/packages/openci_workflow/versions/0.8.1) · [CLI](https://pub.dev/packages/openci_cli_plus/versions/0.9.0)

## LinuxでDartテストを実行する

ホスト型Linuxランナーは、対象チームとリポジトリごとに有効化するパイロットです。SDK 0.8.0から、従来の `MachineType.linuxLatest` を使っていたワークフローは次のいずれかを選びます。どちらも1分0.1円で、チーム全体で月にLinuxを200分使った場合は20円です。[料金表](/ja/pricing/)

| ワークフローの指定        | vCPU | メモリ |
| ------------------------- | ---: | -----: |
| `MachineType.linuxSmall`  |    1 |  2 GiB |
| `MachineType.linuxMedium` |    2 |  4 GiB |

たとえば、リポジトリ直下のDartパッケージをテストするなら、次のファイルを `openci/checks/unit.dart` に置けます。この例では `docs/` 配下とルートの `README.md` だけを変えたPRのチェックは `skipped` になり、VMの利用時間は発生しません。

```dart
import 'package:openci_workflow/openci_workflow.dart';

Future<void> main() async {
  final ci = await OpenCI.init(
    workflowName: 'Dart unit tests',
    machine: MachineType.linuxSmall,
    ciTriggers: [
      CITrigger.pullRequest(
        branch: '*',
        pathsIgnore: ['docs/**', 'README.md'],
      ),
    ],
  );
  await ci.dart.test();
}
```

同じPRで `lib/` のファイルも変えれば、テストは実行されます。`pathsIgnore` はpushにも使えます。トリガーごとに、実行したいパスを `paths` で指定するか、除外したいパスを `pathsIgnore` で指定します。

ワークフローは `openci/` 配下のサブディレクトリからも検出されます。OpenCI自身も19本の定義を機能・OS別に整理しました。たとえばAndroidとiOSで同じ `patch.dart` というファイル名を使い、それぞれ独立したジョブとして実行できます。[OpenCIのワークフロー構成](https://github.com/openci-org/openci/tree/v2.7.0/openci)

Linuxの実機検証では、1台のRyzenマシンでAndroid 15のエミュレーターを2台並行して動かし、両方でボタンをタップするE2Eテストが通りました。この検証に使ったVMはそれぞれ7 vCPU・6.5 GiBです。[検証結果](https://github.com/openci-org/openci/pull/4056)

## どのPRの、どのステップが失敗したかを調べる

同じコミットから `main` とリリースブランチにPRを出すと、マージ先によってテスト結果が変わることがあります。OpenCIはGitHubが各PRのマージ結果を検証するために作るコミットに、そのPRのチェック結果を記録します。チェックの **Details** を開くと、そのジョブのログに直接移動できます。[PRごとのチェック](https://github.com/openci-org/openci/pull/4059) · [ログへのリンク](https://github.com/openci-org/openci/pull/4043)

Codexから調べる場合は、CLIでログインしてチームを選び、ローカルのMCPサーバーを登録します。

```sh
dart install openci_cli_plus
openci login
codex mcp add openci -- openci mcp
```

新しいチャットにPRのURLを貼って「どのステップで失敗した？　エラーの前後のログを見せて」と頼めます。`find_jobs` が該当ジョブを探し、`get_job_logs` が失敗ステップとその前後のログを返します。特定のコミットを調べるときは、リポジトリ名と完全なコミットSHAを渡せます。[CLIガイド](/ja/docs/cli/)

## 1回のShorebirdリリースからAPKとAABを配布する

AndroidのQAにはFirebase App DistributionでAPKを配り、Google Playの内部テストにはAABを送る場合、SDK 0.7.0からは1回のShorebirdリリースで両方のファイルが揃います。`ci.shorebird.releaseApk()` を使っていた箇所を `releaseAndroid()` に変更し、各配布先に `apkPath` と `aabPath` を渡します。

次は、署名と各サービスの認証を用意した配布ワークフローの例です。v2.7.0では、チームのシークレットを使うこの配布ジョブをmacOSで実行します。`androidAppId` はFirebaseのAndroidアプリID、2つの認証情報は各サービスアカウントのJSONをBase64にした値です。

```dart
final files = await ci.shorebird.releaseAndroid(flutterVersion: '3.47.8');
await ci.flutter.deployApkToFirebaseAppDistribution(
  apkPath: files.apkPath,
  appId: androidAppId,
  serviceAccountJsonBase64: firebaseCredentials,
  groups: ['qa'],
);
await ci.flutter.deployAabToPlayConsole(
  aabPath: files.aabPath,
  packageName: 'com.example.app',
  serviceAccountJsonBase64: playCredentials,
);
```

`qa` にはFirebaseに登録済みのグループエイリアスを指定します。個別に配布するときは `testers` にメールアドレスを渡せます。Google Playの配布先は既定で内部テストです。[Shorebirdの変更](https://github.com/openci-org/openci/pull/4061) · [Androidのテスター配布](https://github.com/openci-org/openci/pull/4048)

## TestFlight、Flutter Web、公式サイトの更新

- 標準暗号化を申告するアプリは、**TestFlightへの配信**時に `deployIpaToTestFlight()` の `exportCompliance` 引数に `TestFlightExportCompliance.standardEncryption(...)` を指定できます。用途説明とフランスでの配信予定を指定すると、SDKが一致する申告を検索または作成し、Appleの承認または免除を処理済みのビルドに反映します。Appleの書類審査が必要な場合は、承認後に `applyTestFlightExportCompliance()` で同じビルドに適用できます。[TestFlightの申告](https://github.com/openci-org/openci/pull/4054)
- **Flutter Webのリリースビルド**には `ci.flutter.buildWeb()` を使えます。OpenCI Dashboardでは依存解決後に `buildWeb(noPub: true)` を呼び、生成した `build/web` をPRのFirebase Hostingプレビューと本番公開に使っています。[Dashboardのワークフロー](https://github.com/openci-org/openci/blob/v2.7.0/openci/dashboard/web/hosting.dart)
- **公式サイトの日英トップページ**に、FlutterのPRテストやアプリ配布の流れを試せるデモを追加しました。スポンサー、マシンの提供者、インフラで支えてくださっている方々も紹介しています。[ワークフローデモ](/ja/) · [Special Thanks](/ja/thanks/)
