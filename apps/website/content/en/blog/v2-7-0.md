We released OpenCI v2.7.0 on November 27. To try the Dart examples below, set `openci_workflow` to `^0.8.1` in `openci/pubspec.yaml`. The pull request walkthrough uses `openci_cli_plus` 0.9.0. [Workflow SDK](https://pub.dev/packages/openci_workflow/versions/0.8.1) · [CLI](https://pub.dev/packages/openci_cli_plus/versions/0.9.0)

## Run Dart tests on Linux

The hosted Linux pilot is enabled per team and repository. Starting with SDK 0.8.0, workflows using `MachineType.linuxLatest` must choose one of two sizes. Under yen billing, both Linux runners cost ¥0.1 per minute and macOS costs ¥1 per minute. Running 200 minutes of E2E tests in a month costs ¥20 on Linux and ¥200 on macOS. [Yen pricing (Japanese)](/ja/pricing/)

| Workflow setting          | vCPUs |   RAM |
| ------------------------- | ----: | ----: |
| `MachineType.linuxSmall`  |     1 | 2 GiB |
| `MachineType.linuxMedium` |     2 | 4 GiB |

For a Dart package at the repository root, save the following workflow as `openci/checks/unit.dart`. A pull request that changes only the documentation paths below gets a `skipped` check and uses no VM time.

```dart
import 'package:openci_workflow/openci_workflow.dart';

Future<void> main() async {
  final ci = await OpenCI.init(
    workflowName: 'Dart unit tests',
    machine: MachineType.linuxSmall,
    ciTriggers: [
      CITrigger.pullRequest(
        branch: '*',
        pathsIgnore: ['docs/**', 'README.md'],
      ),
    ],
  );
  await ci.dart.test();
}
```

Change a file under `lib/` in the same PR and the tests run. Push triggers also accept `pathsIgnore`. Each trigger takes one path filter. Use `paths` to list the changes that start a run, or `pathsIgnore` to list the ones to skip.

OpenCI also discovers workflows in subdirectories of `openci/`. We moved our own 19 definitions into directories by feature and platform. Our Android and iOS patch workflows can both be named `patch.dart` and run as separate jobs. [OpenCI’s workflow tree](https://github.com/openci-org/openci/tree/v2.7.0/openci)

To test Linux concurrency on hardware, we ran two Android 15 emulators on a single Ryzen host. Each VM had 7 vCPUs and 6.5 GiB of RAM. Both completed a button-tap E2E test while their execution times overlapped. [Test results](https://github.com/openci-org/openci/pull/4056)

## Find the failing step for a particular pull request

A commit can pass when merged into `main` and fail when merged into a release branch. OpenCI now reports each check against the commit GitHub created to test that PR’s merge. Select **Details** on the check to open the log for that job. [PR checks](https://github.com/openci-org/openci/pull/4059) · [Run log links](https://github.com/openci-org/openci/pull/4043)

To investigate from Codex, sign in to the CLI, select your team, and register the local MCP server.

```sh
dart install openci_cli_plus
openci login
codex mcp add openci -- openci mcp
```

In a new chat, paste a PR URL and ask “Which step failed? Show me the log around the error.” The `find_jobs` tool locates the jobs, and `get_job_logs` returns the failing step and the surrounding output. To narrow the search to one revision, provide the repository and full commit SHA. [CLI guide](/en/docs/cli/)

## Distribute an APK and an app bundle from one Shorebird release

A team might send an APK to QA through Firebase App Distribution and an AAB to Google Play’s internal track. Starting with SDK 0.7.0, one Shorebird release produces both files. Migrate calls to `ci.shorebird.releaseApk()` to `releaseAndroid()`, then pass its `apkPath` and `aabPath` to the two distributors.

This excerpt assumes signing and service credentials are already configured. In v2.7.0, run this distribution job on macOS to use team secrets. `androidAppId` is the Firebase Android app ID. The two credential values hold the respective Base64-encoded service account JSON files.

```dart
final files = await ci.shorebird.releaseAndroid(flutterVersion: '3.47.8');
await ci.flutter.deployApkToFirebaseAppDistribution(
  apkPath: files.apkPath,
  appId: androidAppId,
  serviceAccountJsonBase64: firebaseCredentials,
  groups: ['qa'],
);
await ci.flutter.deployAabToPlayConsole(
  aabPath: files.aabPath,
  packageName: 'com.example.app',
  serviceAccountJsonBase64: playCredentials,
);
```

Use a group alias registered in Firebase for `qa`. To distribute to individuals, pass email addresses in `testers`. The Google Play helper defaults to the internal track. [Shorebird change](https://github.com/openci-org/openci/pull/4061) · [Android tester distribution](https://github.com/openci-org/openci/pull/4048)

## TestFlight, Flutter Web, and the OpenCI website

- When uploading to **TestFlight**, apps that declare standard encryption can pass `TestFlightExportCompliance.standardEncryption(...)` as the `exportCompliance` argument to `deployIpaToTestFlight()`. Supply the app’s purpose and whether you plan to distribute it in France. The SDK finds or creates the matching declaration and applies Apple’s approval or exemption to the processed build. If Apple requests documentation, use `applyTestFlightExportCompliance()` on the same build after approval. [TestFlight declarations](https://github.com/openci-org/openci/pull/4054)
- **Flutter Web workflows** can build a release with `ci.flutter.buildWeb()`. The OpenCI Dashboard calls `buildWeb(noPub: true)` after resolving dependencies, then uses `build/web` for both PR previews and production on Firebase Hosting. [Dashboard workflow](https://github.com/openci-org/openci/blob/v2.7.0/openci/dashboard/web/hosting.dart)
- **The English and Japanese homepages** now have an interactive demo of Flutter PR checks and app distribution. Our Special Thanks page introduces the sponsors and contributors who provide machines and infrastructure for OpenCI. [Workflow demo](/en/) · [Special Thanks](/en/thanks/)
