What does the second phone actually receive when the first one writes a value over Bluetooth Low Energy (BLE)? In OpenCI v2.6.0 you can check both ends of that exchange in CI. The Flutter example runs on two iOS simulators on the same Mac and uses a virtual Bluetooth connection.

## Follow one value across two screens

The workflow builds the Patrol test once and installs it on both simulators. Simulator B first publishes a readable GATT characteristic. Simulator A reads it, then writes a fresh 16-byte value. B displays the value and sends it back. The test passes when the bytes recorded by both apps match.

To try it, check out the v2.6.0 tag on a Mac with Flutter 3.47.8, Python 3.13, Xcode and an iOS Simulator runtime. Run these commands from the repository root.

```sh
flutter pub get
dart run openci/virtual_ble_ci.dart
```

To use the same setup in your own Patrol test, call `openCI.patrol.testWithVirtualBle()`. It returns a directory with each simulator’s log and XCTest result bundle. The example also asks both apps for a JSON file so the workflow can compare what each peer received. [Flutter example](https://github.com/openci-org/openci/tree/v2.6.0/packages/openci_virtual_ble) · [Workflow SDK 0.5.3](https://pub.dev/packages/openci_workflow/versions/0.5.3)

## Find the failing line from a pull request

When a PR workflow fails or times out, OpenCI can post a summary in the PR conversation. For recognized diagnostics, the line number links to the file at the commit that CI tested. A repeat failure updates the same comment. Once the workflow passes, the comment marks it resolved and folds away the previous errors. You can retry an eligible, finished macOS job from its detail page in the dashboard. [Failure comment example](https://github.com/openci-org/openci/pull/4010#issuecomment-7009043736) · [Dashboard retries](https://github.com/openci-org/openci/pull/3959)

## Deploy from a published release

Earlier this week, v2.5.1 added GitHub Release triggers. Set `CITrigger.release(tag: 'v*')` to run a workflow when a matching release is published. OpenCI reads the workflow at the tagged commit. The published `openci_workflow` 0.5.3 SDK adds `openCI.firebase.functions.deploy()`, which uses the installed Firebase CLI. Supply a project ID and, to deploy a single codebase, its name. [Release triggers](https://github.com/openci-org/openci/pull/3993) · [Firebase Functions example](https://github.com/openci-org/openci/blob/v2.6.0/packages/openci_workflow/README.md#firebase-functions)

On the web dashboard, Cloud teams can now see their estimated CI spend for the month above the build list. Select the amount to open the team’s billing details. [Monthly CI spend](https://github.com/openci-org/openci/pull/3989)
